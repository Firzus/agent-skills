# Track work and close feedback

## 1. Locate and triage

Read the existing Linear record and relevant linked artifacts before creating anything. Preserve the reporter's intent and channel privacy. Classify incoming work as ready, deferred with a reason, duplicate linked to its owner, or declined with an explanation.

Keep one coherent outcome in its existing issue. Separate work only for independent responsibility, real dependencies, or independently accepted results; this does not authorize additional Codex tasks or external issues. Retain simple answers in the current conversation without generating administrative work.

**Done when:** the authoritative record and disposition are known, or missing Linear access is explicit.

## 2. Select ready work and maintain responsibility

For a next-task request, inspect accepted priorities, prerequisites, unresolved decisions, and existing ownership. Select the highest-priority unblocked item that fits the authorized scope and available owner; avoid claiming work already in progress elsewhere. Break ties using the project's agreement or ask when the choice materially affects direction. If none is ready, identify the decision or dependency to unblock rather than inventing new scope.

Clarify only missing outcome, owner, reviewer, acceptance evidence, delivery boundary, and next action. One person may hold multiple roles. Map actual Linear states to these meanings without renaming the team's workflow:

| Meaning | Evidence |
| --- | --- |
| Ready | Outcome, prerequisites, responsibility, and completion boundary are clear |
| In progress | Work has actually started |
| Review | The result and verification evidence are available to the reviewer |
| Done | All required acceptance and delivery conditions are satisfied |

The implementer maintains progress and evidence; the designated reviewer accepts the result. Non-code work uses its own artifact and review, not an artificial PR.

A blocker preserves the current phase and records cause, resolution owner, dependency if applicable, and next action, using the team's existing representation. Cancellation and duplicate closure are distinct from successful completion.

**Done when:** the selected work, state, and responsibility reflect observed facts, with missing conditions explicit.

## 3. Link evidence and update

Update Linear on meaningful changes through the entry point's authorization and verification checks, not after every tool call. Link the GitHub PR and relevant check or review evidence to its Linear work, and include the Linear reference in the PR using the project's linking convention. Avoid copying the same progress report into multiple backlogs.

Record acceptance, integration, and deployment as separate facts. A merged PR or automated Linear closure proves neither acceptance nor deployment. If native status has advanced before required acceptance, report that discrepancy and reconcile it only within the authorized write scope; otherwise leave the correction pending. Do not claim the recorded status already changed.

On a failed or unverifiable update, preserve the last confirmed state, intended change, failure evidence, and next action in the current task. Check for partial success before retrying to avoid duplicate issues or comments.

**Done when:** changes are verified in Linear or reported pending, and artifact links support rather than overstate progress.

## 4. Preserve continuity and close feedback

At a handoff or interruption, preserve the objective, completed work, artifact and check evidence, remaining decisions or blockers, owner, and next action in the existing record. On resumption, reconcile that checkpoint with current artifacts and state.

Return the known disposition or outcome through the approved intake channel in the reporter's terms. Protect private implementation details. Keep feedback explicitly pending when its destination is unavailable or not authorized.

**Done when:** the next owner can resume, required completion conditions are met or named, and the reporter has the authorized outcome or an explicit pending update.
