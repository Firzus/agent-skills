# Frameworks

The named frameworks, what each is actually for, and how they compose. None
replaces the design process in `SKILL.md` — they are lenses inside it.

| Framework | Author | Core idea | Best used for | Caveat |
|---|---|---|---|---|
| **SDT / PENS** | Deci & Ryan; Ryan & Rigby | Competence, autonomy, relatedness drive intrinsic motivation | Evaluating whether a design sustains motivation long term | Theory, not a design method |
| **6D (Six Steps)** | Werbach & Hunter, *For the Win* | Define objectives → Delineate behaviors → Describe players → Devise activity loops → Don't forget fun → Deploy tools | The design *process*; forces objectives before mechanics | Deliberately puts mechanics last |
| **B=MAP** | BJ Fogg | Behavior = Motivation × Ability × Prompt | Diagnosing why a target behavior isn't happening | Per-behavior lens, not whole-system |
| **Octalysis** | Yu-kai Chou | 8 core drives; **white hat** (Epic Meaning, Accomplishment, Creativity/Feedback) vs **black hat** (Scarcity, Unpredictability, Loss & Avoidance) | Auditing which motivational levers a product uses and misses | Widely cited, not experimentally validated |
| **HEXAD** | Marczewski; validated scale by Tondello et al. 2016 | 6 user types mapped to preferred design elements | Segmenting users and choosing element mixes | Validated 24-item scale — unlike Bartle |
| **Hooked** | Nir Eyal | Trigger → Action → Variable Reward → Investment habit loop; Manipulation Matrix as ethics check | Habit-loop analysis for recurring-use products | Same loop powers manipulative apps — pair with the ethics gate |
| **RECIPE** | Scott Nicholson | Reflection, Exposition, Choice, Information, Play, Engagement — reward-free elements | Long-term behavior change where rewards would undermine motivation | Framework, not experimentally validated |
| **Bartle types** | Richard Bartle | Achievers / Explorers / Socializers / Killers | Historical vocabulary only | Built for MUDs; Bartle himself says don't use it for gamified apps — prefer HEXAD |

## How they compose

- **SDT + flow** explain *why* something motivates.
- **B=MAP** explains *when* a single behavior fires.
- **6D** gives the *process* (mirrored by the steps in `SKILL.md`).
- **Octalysis + HEXAD** give *audit vocabularies* — drives present/missing,
  user types served/ignored.
- **Hooked** describes the *retention loop* mechanically.
- **RECIPE + white-hat/black-hat** give the *ethical frame*.

## HEXAD user types

| Type | Motivated by |
|---|---|
| Philanthropist | Purpose, altruism |
| Socialiser | Relatedness |
| Free Spirit | Autonomy, exploration |
| Achiever | Competence, mastery |
| Player | Extrinsic rewards — responds, but fragile |
| Disruptor | Change, testing limits (rare type) |

Population skews Philanthropist / Free Spirit / Achiever — meaning, autonomy,
and mastery — which is why reward-and-competition-only designs miss most
users.
