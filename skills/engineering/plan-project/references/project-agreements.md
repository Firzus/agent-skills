# Establish project-specific instructions

Use AGENTS.md as the project instruction file. Inspect it and the repository before proposing additions. A missing file does not by itself require a new planning exercise for a small task.

## Gather evidence

Inspect architecture boundaries, generated files, registration points, existing checks, documentation locations, shared resources, and current tracking agreements. Follow configuration and scripts rather than copying easily discoverable commands into instructions.

Identify non-obvious constraints that prevent harmful or misleading changes. Verify each proposed guardrail and its reason. Preserve local settings and credentials; never store secret values in instructions.

## Ask only for project decisions

Resolve from existing agreements where possible:

- constraints, target environments, and non-obvious architecture obligations;
- testing boundaries, deliberate exclusions, and required verification;
- the documentation home and any system-page conventions;
- accountable owners, reviewers, and shared-resource coordination;
- the tracker or existing task record, intake channel, native state mapping, and completion conditions;
- the expressly authorized destinations and actions for agent updates.

The tracking arrangement is chosen per project. Team size alone does not impose Linear or another service. Reuse a lightweight current record when it is sufficient. No tool choice grants access.

## Confirm and write

Include only project-specific values and verified constraints not already carried by the shared method or readily discoverable configuration. Tool schemas, available model inventories, and session paths belong to the environment.

User-supplied exact changes or a previously accepted proposal authorize the corresponding edit. Present materially new project conventions for acceptance before writing. Update the relevant sections of AGENTS.md, create it only when needed, and preserve unrelated content. Keep unresolved choices in the task record rather than inventing identifiers, roles, or permissions.

Report what was written and whether instruction loading was actually verified in the target environment. Preparing instructions is not installing skills, configuring the repository, or proving client support.

**Done when:** accepted project conventions have a single clear home, their source or rationale is known, and unconfigured or unverified parts remain explicit.
